## 一、项目概述

FinTax AI 是一个**企业财税智能查询与分析平台**，面向税务师事务所、集团企业和普通企业用户，提供自然语言驱动的财税数据查询、税收优惠智能匹配、法规知识检索、企业画像分析和多轮对话综合分析等功能。

系统核心能力是将用户的自然语言问题自动转化为 SQL 查询，从 SQLite 数据库中检索数据，并通过 LLM 生成专业的财税数据解读，实现"问即答"的智能交互体验。

### 核心特性

| 特性 | 说明 |
|------|------|
| 自然语言查询 | 用户以中文自然语言提问，系统自动解析意图并生成 SQL |
| 多域数据覆盖 | 覆盖增值税、企业所得税、资产负债表、利润表、现金流量表、科目余额、发票、财务指标、跨域共 9 大数据域 |
| 三路由分流 | 自动将查询分流至财务数据查询、税收优惠查询、法规知识库查询三条路径 |
| 智能缓存 | L1 精确缓存 + L2 模板缓存二级体系，支持跨纳税人复用 |
| 多轮对话 | 支持上下文继承、代词解析和跨路由混合分析 |
| 企业画像 | 自动聚合多域数据生成企业画像，支持 LLM 驱动的分析报告 |
| RBAC 权限 | 5 级角色体系，企业级数据隔离 |
| 双准则适配 | 自动适配企业会计准则(ASBE)和小企业会计准则(ASSE) |

## 三、功能模块详细说明

### 3.1 智能对话查询

#### 3.1.1 自然语言查询

用户在对话界面输入中文问题，系统自动完成以下处理：

1. **意图路由**：将问题分流到财务数据查询、税收优惠查询或法规知识库查询
2. **实体预处理**：提取纳税人、期间、域等结构化实体信息
3. **意图解析**：通过 LLM 将问题解析为结构化意图 JSON（域、指标、过滤条件等）
4. **SQL 生成**：根据意图和 schema 约束，通过 LLM 生成安全的 SQL
5. **SQL 审核**：对生成的 SQL 进行安全审核（视图白名单、危险关键字拦截等）
6. **数据查询**：执行审核通过的 SQL，从数据库获取结果
7. **展示格式化**：将查询结果转换为中文表头、格式化数值的展示数据
8. **LLM 解读**：对查询结果生成专业的财税数据解读分析

**支持的查询类型**：

| 查询类型 | 示例 | 处理路径 |
|----------|------|----------|
| 单域单指标 | "华兴科技2025年增值税应纳税额是多少" | 标准 NL2SQL 管线 |
| 单域多指标 | "华兴科技2025年各季度营业收入和利润" | 标准 NL2SQL 管线 |
| 跨域查询 | "华兴科技2025年资产负债率和净利润" | 跨域管线（并行 LLM） |
| 财务指标 | "华兴科技2025年毛利率趋势" | 财务指标管线（域锁定优化） |
| 计算指标 | "华兴科技2025年资产负债率" | 计算指标管线（确定性，无 LLM） |
| 概念查询 | "华兴科技2025年各月采购金额" | 概念管线（确定性 SQL） |
| 构成分析 | "华兴科技2025年资产构成" | 标准 NL2SQL 管线（UNION ALL） |
| 税收优惠 | "高新技术企业有哪些税收优惠" | 税收优惠知识库 |
| 法规查询 | "增值税留抵退税的最新政策" | Coze RAG 法规知识库 |

#### 3.1.2 意图路由

系统通过分层关键词匹配将查询分流到三条主路由：

| 路由 | 说明 | 触发条件 |
|------|------|----------|
| `financial_data` | 财务数据查询 | 数据类关键词 + 税种关键词同时出现，或纳税人名称匹配 |
| `tax_incentive` | 税收优惠查询 | 优惠关键词（排除特定否定词） |
| `regulation` | 法规知识库查询 | 流程/操作类关键词，或默认兜底 |

#### 3.1.3 实体预处理

从用户查询中自动提取以下实体信息：

| 实体类型 | 提取方式 | 示例 |
|----------|----------|------|
| 纳税人 | 精确匹配 + 模糊前缀匹配 | "华兴科技" → taxpayer_id |
| 年度 | 正则提取 + 相对日期 | "去年" → 2025 |
| 月份 | 正则提取 + 范围 | "3-6月" → month_start=3, month_end=6 |
| 季度 | 正则提取 | "Q1" → period_quarter=1 |
| 域 | 关键词优先级检测 | "增值税" → vat |
| 会计准则 | 数据库查询推断 | 一般纳税人 → 企业会计准则 |

**相对日期支持**：今年、去年、前年、本月、上个月、上个季度、上半年、下半年、最近N个月、过去N年

#### 3.1.4 域检测

系统覆盖 9 大数据域，通过关键词优先级进行域识别：

| 优先级 | 域 | 典型关键词 |
|--------|------|-----------|
| 0 | financial_metrics | 毛利率、净利率、ROE、资产负债率 |
| 1 | cash_flow | 经营活动现金流、投资活动净现金流 |
| 2 | account_balance | 借方发生额、贷方发生额、期初余额 |
| 3 | profit | 营业收入、营业利润、净利润 |
| 4 | balance_sheet | 资产总计、负债合计、所有者权益 |
| 5 | eit | 应纳税所得额、所得税费用 |
| 6 | invoice | 进项发票、销项发票、发票金额 |
| 7 | vat | 增值税、销项税、进项税 |

**跨域检测**：当查询同时包含多个域的独有关键词时，自动升级为 `cross_domain`

#### 3.1.5 SQL 安全审核

对 LLM 生成的 SQL 执行 10 条核心审核规则：

| 规则 | 说明 |
|------|------|
| 单语句 | 不允许中间分号 |
| 只读 | 必须 SELECT/WITH 开头 |
| 危险关键字 | 禁用 DROP、DELETE、INSERT、UPDATE、ALTER 等 |
| 视图白名单 | FROM/JOIN 的表必须在允许列表中 |
| 禁止 SELECT * | 必须明确指定列 |
| taxpayer_id 过滤 | 必须包含纳税人过滤条件 |
| 期间过滤 | 必须包含年份/月份/季度过滤 |
| 行数限制 | 必须有 LIMIT 子句 |
| 危险函数 | 禁用 LOAD_EXTENSION、WRITEFILE 等 |
| 系统表 | 禁止访问系统表 |

审核失败时自动重试一次，将违规信息反馈给 LLM 重新生成。

#### 3.1.6 LLM 数据解读

系统根据查询结果自动检测 8 种分析场景，生成针对性的解读：

| 场景 | 说明 | 分析重点 |
|------|------|----------|
| 单指标单期间 | 如"2025年增值税应纳税额" | 绝对值评估、行业对比 |
| 单指标多期间 | 如"2025年各月增值税趋势" | 趋势分析、环比变化 |
| 多指标单期间 | 如"2025年Q1各项利润指标" | 指标间关系、结构分析 |
| 多指标多期间 | 如"2025年各季度收入和利润" | 趋势对比、关联分析 |
| 财务指标单期间 | 如"2025年毛利率" | 评价等级、行业对比 |
| 财务指标多期间 | 如"2025年各季度毛利率趋势" | 趋势分析、预警 |
| 计算指标 | 如"资产负债率" | 公式解读、风险提示 |
| 跨域 | 如"资产负债率和净利润" | 跨域关联、综合分析 |

支持 `detailed`（详细）和 `standard`（简短）两种解读模式。

### 3.2 多轮对话

#### 3.2.1 上下文继承

系统支持多轮对话的上下文继承，包括：

- **代词解析**：将"它/那/这个/该/上述"解析为上一轮的纳税人实体
- **隐式继承**：当查询不含纳税人或时间信息时，自动继承上一轮的实体
- **域中性检测**：查询不包含任何域关键词时，继承上一轮的域

#### 3.2.2 混合分析

当用户勾选"多轮对话"模式且对话历史包含 ≥2 种路由时，系统可触发跨路由混合分析：

1. 检测历史对话中使用的路由类型（financial_data / tax_incentive / regulation）
2. 调用 LLM 判断当前查询是否需要综合分析历史数据
3. 从历史对话中按路由分组提取数据
4. 使用税务筹划专家提示词模板进行综合分析

分析维度包括：数据匹配分析、风险识别、税收筹划建议、财务优化建议、行动计划。

### 3.3 税收优惠查询

系统内置税收优惠政策知识库（SQLite FTS5 全文索引），采用四级搜索策略：

| 级别 | 搜索方式 | 说明 |
|------|----------|------|
| Tier 0.5 | 类别搜索 | 按税种类别和类别关键词匹配 |
| Tier 1 | 结构化搜索 | 按税种+实体关键词精确匹配 |
| Tier 2 | 实体搜索 | 按实体关键词模糊匹配 |
| Tier 3 | 关键词搜索 | LIKE 模糊匹配 |
| Tier 4 | FTS5 全文搜索 | 全文索引搜索 |

搜索完成后，调用 LLM 对结果生成自然语言摘要。

### 3.5 企业画像

#### 3.5.1 画像数据聚合

系统从数据库各域视图/表中提取数据，聚合为企业画像结构化 JSON，包含以下模块：

| 模块 | 数据来源 | 说明 |
|------|----------|------|
| 基本信息 | taxpayer_info | 纳税人名称、类型、行业、信用等级等 |
| 资产结构 | vw_balance_sheet_* | 资产/负债/权益结构及占比 |
| 利润数据 | vw_profit_* | 营业收入、利润总额、净利润等 |
| 现金流量 | vw_cash_flow_* | 经营/投资/筹资活动现金流 |
| 成长指标 | 多表计算 | 营收增长率、利润增长率 |
| 财务指标 | financial_metrics_item | 毛利率、净利率、ROE 等 |
| 税务汇总 | vw_vat_* + vw_eit_* | 增值税、所得税、综合税负率 |
| 发票统计 | vw_inv_spec_* | 进项/销项发票统计 |
| 研发创新 | eit_annual_basic_info | 研发费用、高新认定 |
| 跨境业务 | eit_annual_basic_info | 海外关联交易 |
| 合规风险 | 多表综合 | 信用等级、申报连续性 |
| 股东信息 | eit_annual_shareholder | 股东名称、持股比例、分红 |
| 员工结构 | hr_employee_info | 员工人数、学历、岗位分布 |

#### 3.5.2 指标评价

系统对 9 个核心财务指标进行自动评价分级：

| 指标 | 优秀 | 良好 | 偏高/一般 | 风险/偏低 |
|------|------|------|-----------|-----------|
| 资产负债率 | ≤30% | ≤50% | ≤70% | >70% |
| 流动比率 | >2.0 | ≤2.0 | ≤1.5 | <1.0 |
| 毛利率 | >40% | ≤40% | ≤20% | <10% |
| 净资产收益率 | >20% | ≤20% | ≤10% | <5% |
| 营收增长率 | >20% | ≤20% | ≤10% | <0% |
| 综合税负率 | <2% | ≤5% | ≤10% | >10% |

#### 3.5.3 画像报告生成

基于企业画像数据，通过 LLM 流式生成专业的企业画像分析报告，覆盖 14 个分析模块：

1. 企业身份与股权治理
2. 组织与人力
3. 财务表现
4. 业务运营
5. 购销存/供应链
6. 研发创新
7. 税务表现
8. 跨境业务
9. 合规风险
10. 外部关系
11. 数字化
12. 环境、社会和公司治理(ESG)
13. 政策匹配
14. 特殊业务

报告末尾自动生成"企业全景综合结论"，覆盖经营健康度、财务状况、税务合规水平、涉税风险分级、税收优惠与筹划机会、管理建议 6 个维度。

**报告管理功能**：
- 报告列表（分页浏览）
- 报告生成状态跟踪（generating → completed/failed）
- 报告删除
- 断线续传（前端断开后后台继续生成）

### 3.8 用户与权限管理

#### 3.8.1 角色体系

系统采用 5 级 RBAC 角色体系：

| 角色 | 标签 | 可创建角色 | 数据权限 |
|------|------|-----------|----------|
| sys | 超级管理员 | admin, firm, group, enterprise | 全部企业 |
| admin | 系统管理员 | admin, firm, group, enterprise | 全部企业 |
| firm | 事务所用户 | firm, enterprise | 授权企业 |
| group | 集团企业用户 | group, enterprise | 授权企业 |
| enterprise | 普通企业用户 | enterprise | 授权企业 |

#### 3.8.2 企业数据隔离

- 每个用户通过 `user_company_access` 表关联可访问的企业
- sys/admin 角色可访问全部企业数据
- 其他角色只能访问授权企业的数据
- 创建用户时自动分配角色默认企业
- 非 admin 只能分配自己有权限的企业子集

#### 3.8.3 用户管理功能

| 功能 | 说明 |
|------|------|
| 用户列表 | 查看所有用户（admin+） |
| 创建用户 | 设置用户名、密码、角色、关联企业 |
| 更新用户 | 修改密码、角色、显示名、启用状态 |
| 删除用户 | 不可删除自己，不可删除 sys 角色 |
| 企业权限管理 | 为用户分配/移除可访问的企业 |

#### 3.8.4 认证机制

- **验证码门控**：首次访问需通过验证码验证
- **JWT 认证**：登录后签发 JWT Token（HS256，24 小时有效期）
- **密码加密**：使用 bcrypt 加密存储
- **自动鉴权**：所有 API 请求自动注入 Bearer Token

| 功能 | 说明 |
|------|------|
| 历史记录列表 | 分页浏览，支持按分类过滤（财务数据/税收优惠/法规/混合分析） |
| 搜索 | 按查询内容搜索历史记录 |

| 软删除 | 标记删除，支持恢复（admin+） |

### 3.10 缓存体系

#### 3.10.1 L1 精确缓存

- **缓存键**：`MD5(company_id + normalized_query + response_mode)`
- **存储内容**：完整管线结果（查询结果 + 解读文本）
- **存储格式**：JSON 文件（`cache/{md5}.json`）
- **淘汰策略**：LRU，上限 1200 个文件
- **适用场景**：完全相同的查询直接返回缓存结果

#### 3.10.2 L2 模板缓存

- **缓存键**：按域类型使用不同维度组合
  - 财务报表域：`MD5(query + response_mode + fs + accounting_standard)`
  - 增值税域：`MD5(query + response_mode + vat + taxpayer_type)`
  - 所得税域：`MD5(query + response_mode + eit)`
- **存储内容**：SQL 模板（纳税人 ID 替换为占位符）
- **淘汰策略**：LRU，上限 600 个文件
- **适用场景**：不同纳税人但相同类型/准则的查询可复用 SQL 模板

#### 3.10.3 思考模式与缓存策略

| 思考模式 | L1 缓存命中 | L2 缓存命中 | 缓存未命中 |
|----------|-------------|-------------|-----------|
| quick | 返回缓存结果+缓存解读 | 实例化 SQL 并执行 | 完整管线 |
| think | 返回缓存结果+重新解读 | 实例化 SQL 并执行 | 完整管线 |
| deep | 不使用缓存，直接走完整管线 | 不使用缓存 | 完整管线 |

## 四、数据域详细说明

### 4.1 增值税 (VAT)

**数据表**：`vat_return_general`（一般纳税人）、`vat_return_small`（小规模纳税人）

**查询视图**：`vw_vat_return_general`、`vw_vat_return_small`

**核心字段**：

| 字段 | 说明 |
|------|------|
| sales_goods | 货物销售额 |
| sales_services | 应税劳务销售额 |
| output_tax | 销项税额 |
| input_tax | 进项税额 |
| deductible_total | 准予抵扣合计 |
| tax_payable | 应纳税额 |
| total_tax_payable | 应纳税额合计 |
| city_maintenance_tax | 城市维护建设税 |
| education_surcharge | 教育费附加 |

**维度**：item_type（一般项目/即征即退项目）、time_range（本月/累计）

### 4.2 企业所得税 (EIT)

**数据表**：`eit_annual_filing` + `eit_annual_main`（年度）、`eit_quarter_filing` + `eit_quarter_main`（季度）

**查询视图**：`vw_eit_annual_main`、`vw_eit_quarter_main`

**核心字段**：

| 字段 | 说明 |
|------|------|
| revenue | 营业收入 |
| total_profit | 利润总额 |
| taxable_income | 应纳税所得额 |
| tax_payable | 应纳所得税额 |
| actual_tax_payable | 实际应纳所得税额 |
| tax_payable_or_refund | 应补（退）所得税额 |

### 4.3 资产负债表

**数据表**：`fs_balance_sheet_item`（EAV 纵表）

**查询视图**：`vw_balance_sheet_eas`（企业会计准则）、`vw_balance_sheet_sas`（小企业会计准则）

**核心字段**：资产类（货币资金、应收账款、存货等）、负债类（短期借款、应付账款等）、权益类（实收资本、盈余公积等），每个项目含 `begin`（年初余额）和 `end`（期末余额）

### 4.4 利润表

**数据表**：`fs_income_statement_item`（EAV 纵表）

**查询视图**：`vw_profit_eas`（企业会计准则）、`vw_profit_sas`（小企业会计准则）

**核心字段**：营业收入、营业成本、营业利润、利润总额、净利润等

**维度**：time_range（本期/本年累计）

### 4.5 现金流量表

**数据表**：`fs_cash_flow_item`（EAV 纵表）

**查询视图**：`vw_cash_flow_eas`（企业会计准则）、`vw_cash_flow_sas`（小企业会计准则）

**核心字段**：经营活动/投资活动/筹资活动各项流入流出、净现金流

**维度**：time_range（本期/本年累计）

### 4.6 科目余额表

**数据表**：`account_balance`

**查询视图**：`vw_account_balance`

**核心字段**：account_code、opening_balance、debit_amount、credit_amount、closing_balance

**特点**：按会计准则过滤科目（企业会计准则/小企业会计准则对应不同科目集）

### 4.7 发票

**数据表**：`inv_spec_purchase`（进项）、`inv_spec_sales`（销项）

**查询视图**：`vw_inv_spec_purchase`、`vw_inv_spec_sales`

**核心字段**：发票号码、金额、税额、税率、商品名称、发票类型等

### 4.8 财务指标

**数据表**：`financial_metrics_item`

**查询视图**：`vw_financial_metrics`

**指标分类**：盈利能力、偿债能力、营运能力、成长能力、现金流、税负率类等

**维度**：period_type（monthly/quarterly/annual）

### 4.9 跨域查询

跨域查询不使用单一视图，而是通过 UNION ALL 合并多个子域的查询结果。系统严格禁止跨视图 JOIN，确保查询安全性。
